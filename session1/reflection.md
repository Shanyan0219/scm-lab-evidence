1\. 

a) A commit act as a auditable history for traceability in software baseline. I can trace who issues a commit to add new file “teammate.md” into the shared repository, scm-lab-evidence.

b) git is a local version control engine installed in our own computer or machine which allow offline commits and file change. On the contrary, the GitHub serve as a server-based hosting service built in distributed architecture allow collaboration online. I build scm-lab-evidence repo in my local machine but I host the introduction to GitHub exercise and manage pull request using GitHub in browser.



c) Pull request get to tested and reviewed by peers or Change Control Board (CCB) before further merging. It reduces the risk of broken code before merging with main branch due to its isolated changes. 



d) Local machine consist of git init, git add, git commit; while GitHub is git push, git pull and git clone.



2\.

Term 	Description

Repository	A full project folder with its change history

Working tree	Local current set of files to be edit

Staging Area	The list of changes chose to commit

Commit	A snapshot of files with message, author and date.

Branch	A pointer to a alternate line of commits to parallel working from main

Merge	Merging other feature branch with main branch.

Remote	A server-side copy of repository

Push/Pull/Clone	Upload commit / download and integrate new commits / to copy a remote repository to computer.
